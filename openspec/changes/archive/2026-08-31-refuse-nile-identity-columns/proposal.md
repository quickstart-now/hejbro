# Proposal: refuse-nile-identity-columns

## Why

The D106 review of `add-nile-preset` observed (F9, filed as #573) that
identity columns are expressible in the DSL, are sequence-backed exactly
like the refused `serial` family, and had never been measured on Nile.
They have now been measured on the pinned container
(`ghcr.io/niledatabase/testingcontainer@sha256:188a7230d9f39e615bc584d90e8ec6f4754d0ef298701a1d6811d394f3d35696`,
2026-08-31, judgment rule fixed before touching data — a verbatim server
error is a refusal, a verbatim success tag an acceptance):

- `create table … (tenant_id uuid not null, id integer generated always as identity, …, primary key (tenant_id, id))`
  → `ERROR:  IDENTITY columns are not supported for tenant-aware table`
- the `generated by default as identity` form → the same error
- `create table … (tenant_id uuid not null, name text)` (no primary key)
  → `CREATE TABLE`, and an insert under `set local nile.tenant_id` succeeds
- controls: `serial` refused (`type serial is not supported for tenant-aware table`),
  a uuid composite key accepted — both as previously measured

So the preset's promise ("refuse at generate time what the platform
will refuse at apply time") has one more gap to close, and one
"unmeasured" note in the skill can become a measured fact.

## What Changes

- A sixth generate-time validator in `@hejbro/nile`: an identity column
  (either kind) in a tenant-aware table is refused with
  `nile-identity-in-tenant-table`, evidence grade *measured only*, a
  `Next:` pointing at a uuid key. Identity columns outside tenant-aware
  tables are untouched.
- The skill reference records both measurements: identity refused
  (measured), keyless tenant-aware tables accepted (measured) — the
  "unmeasured" notes for these two shapes are replaced.
- `preset-validation`: the Nile requirement gains the identity refusal
  in its SHALL list and evidence paragraph, plus three scenarios
  (identity refused / identity outside tenant tables untouched / keyless
  tenant-aware table accepted as measured). No existing scenario is
  renamed or dropped.
- One `minor` changeset (a new refusal is new behavior for the fixed
  group).

## Capabilities

### Modified Capabilities

- `preset-validation` — the requirement "The Nile preset refuses what
  its platform rejects": one more refused declaration, its evidence, and
  the keyless-table acceptance stated as measured.

## Impact

- `packages/nile/src/validators.ts`, `packages/nile/src/preset.ts`
  (validator list, additive), `packages/nile/test/validators.test.ts`,
  `skills/hejbro/references/nile-preset.md`, the changeset, the ledger.
- No file under `packages/{core,query,cli,pg,supabase,neon}` changes.
  Column order within a primary key stays unmeasured and unclaimed.

## Out of scope

- Measuring or refusing anything else the platform might reject
  (column order in a primary key remains unmeasured).
- #576 (brand names across the polyrepo boundary) and #561.
