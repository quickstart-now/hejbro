### Assistant answer 2

The path: a context-free reviewer that reads only the delta scenario sentences and the public surface, constructs the concrete input that would break each sentence, and runs it live; because it never sees the implementation it is not confined to the shapes the implementer imagined, and each round's prompt accumulates the previous probes. Cause one: the piece's tests came from the same head as the implementation — the file-cycle test only ever fed foreign-key crossings, the key test stopped at two-column collisions, the compose helper was fixed at `foreignKeys: []`, and the round-trip witness compared hejbro with hejbro. Cause two: two rules judged one fact — declarability was "does the key round-trip" on the column side and the D36 regex on the DSL side, and `_id` passed one and failed the other; the loss-report band likewise had no single owner of "who survived", which is why N2, N3 and B1 arrived separately. Cause three: corrections fixed the reported line — R1's cycle fix introduced the preference step that produced R2, and R4's guard sat before the object's own declaration but not before references into it, producing R5-B1. R5-B3 was different in kind: an old lookup by schema and name only, exposed for the first time to a foreign database by this feature.

### Assistant answer 3

Because the piece's way of working validated one example per scenario, and this feature needed a property that holds over any foreign database. Five places let them through. (1) Tasks were bound to examples: under D88 each task starts from one red test derived from a scenario and ends when it is green; "declaration files never import in a cycle" became a two-schema foreign-key test, and the ten-minute sizing left no task in which a four-schema graph or a brownfield fixture could exist. (2) No database hejbro did not create existed in the repository; the scenario prose mentioned one, but tasks derive from scenarios and scenarios describe behavior, not input corpora. (3) The piece reviewer read code against the delta and shared the piece's context; no role constructed inputs — D106 was adopted on 2026-08-28 to fill exactly that gap, and it runs after merge, so it finds late. (4) A delta sentence was written without checking the code: "keeping leading underscores" came from the TypeScript-key side and was never held against core's D36 rule; the rule that the implementer code-checks the planner's sentences came later. And the lead's own share: merge approval rested on green suites without asking what the suites did not measure.

### Assistant answer 4

### Assistant answer 5

Not all. Judged generally the substance is three principles, and expanding them to seven was itself the familiar failure of adding a rule per incident: rules accumulate, agents follow them literally, and they start to contradict — against the owner's standing "fewer process rows" mandate. Per item: (1) property-based testing as wide as the quantifier is sound, but the tag and sizing exemption are marker growth; (2) a golden corpus from the real input domain is sound and the strongest item, the only one that turns review findings into permanent tests; (3) separating the verifier from the generator's context is sound, but it must replace the piece reviewer, not add a stage; (4) is wrongly shaped — a spec citing implementation functions couples spec to code; the general form is that a rule sentence carries examples that become tests; (5) fix the class, record the negative sweep — sound, harmless if confined to correction rounds; (6) enumerating what does not survive a translation between two representations is sound design practice, a checklist item rather than a rule; (7) stating coverage in terms of the input domain is right but becomes a line that says "none". Reduced proposal: build one corpus (2); replace the piece reviewer with a context-free constructor for external-input changes (3, replace not add); rewrite the task rule's "one red test" as "a red test as wide as the sentence" (1, no tag). The rest stay as this correction's disposition practice, not rules.
