## The measurement

Pinned container
`ghcr.io/niledatabase/testingcontainer@sha256:188a7230d9f39e615bc584d90e8ec6f4754d0ef298701a1d6811d394f3d35696`,
2026-08-31 12:51Z, judgment rule fixed before touching data (Rule 50):
a verbatim server error is a refusal, a verbatim success tag an
acceptance; ambiguity resolves against the claim we would like to ship.

- `create table … (tenant_id uuid not null, id integer generated always
  as identity, name text, primary key (tenant_id, id))` →
  `ERROR:  IDENTITY columns are not supported for tenant-aware table`
- the `generated by default as identity` form → the same error, verbatim
- `create table … (tenant_id uuid not null, name text)` — no primary key
  → `CREATE TABLE`; an insert under `set local nile.tenant_id` succeeds
  and the row is visible under that tenant
- controls: `serial` → `ERROR:  type serial is not supported for
  tenant-aware table` (as previously measured); a uuid composite key →
  `CREATE TABLE` (as previously measured)

Two of the skill's "unmeasured" notes became facts pointing in opposite
directions: identity is refused; a keyless tenant-aware table is
accepted. Column order within a primary key stays unmeasured and is
still not claimed.

## What landed

- `nileIdentityValidator` — either identity kind on a tenant-aware table
  is refused with `nile-identity-in-tenant-table`, evidence grade
  measured-only, the verbatim server error in the message, and a `Next:`
  pointing at a uuid key. Tables without `tenant_id uuid` are untouched
  through the same filter the serial validator uses. It is a separate
  refusal with a separate code, not a widening of the serial one,
  because the platform refuses it with its own error.
- Tests: both kinds refused (one diagnostic each, the column named),
  identity outside a tenant-aware table passes, the keyless test renamed
  from "never measured" to "measured: accepted" with its assertion
  unchanged, the preset's validator count 5 → 6, and the all-refusals
  fixture gained an identity column so the `Next:`-loop test covers the
  new code by construction. Mutant: removing the validator from the
  preset's list turns exactly the five identity-related tests red (two
  refusals, two counts, the loop) and nothing else; restored
  byte-identical.
- `preset-validation`: the Nile requirement's SHALL list and evidence
  paragraph gain the identity refusal and the keyless acceptance; three
  scenarios added, none renamed or dropped (a MODIFIED delta, validated
  strict).
- Skill: a new row in the refusal table (code, evidence, the verbatim
  error) and the paragraph that had carried both "unmeasured" notes now
  states the two measurements; the docs test pins the row's tokens.
- One `minor` changeset for the fixed group.

outcomes pre-registered as "refused / accepted" per statement — the
identity result matched the serial family's, the keyless result did not
